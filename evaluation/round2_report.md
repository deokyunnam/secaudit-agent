## 4. 남은 실패 · 한계
- **faithfulness 0.725 (목표 0.80 미달).** mp-07 (0.407)·mp-09 (0.522)·mp-23 (0.431) 이 낮음. 답변이 도구 결과에 없는 일반 설명(예: 조치 방법 예시, 외부 권고의 확장 해석)을 덧붙이는 경향. 다음 개선 후보: 답변 형식에서 "도구 결과에 없는 일반 설명은 '참고' 표시" 규칙, 또는 출력 가드레일에 문장 단위 근거 검사 추가
- **answer_relevancy 0.52.** 표·기준 공백·신규 기준 보고까지 쓰는 긴 형식이라 낮게 나옴 (mp-17·mp-27 은 0.0). 감사 보고 형식상 의도된 길이라 판정 지표로 쓰지 않음
- **도구 선택 불일치 2건:** mp-04 (`search_criteria` 대신 매핑표 근거 사용), mp-25 (데이터 없는 항목이라 도구 없이 "확인되지 않음"). 둘 다 답변은 통과. 기대 도구 설정이 엄격한 편이지만 결과에 맞춰 평가셋을 고치지 않음
- **LLM 응답 편차:** 같은 질문도 회차마다 도구 선택이 달라짐 (mp-02·mp-09 는 1차 X → 2차 O, 프롬프트 변경과 무관). 문항당 1회 실행이라 통과율에 ±1~2건 편차가 있을 수 있음
- **실행 시간 증가 (580초 → 789초):** 차단 요청에서 승인 단계까지 가는 경로가 늘었고(mp-22), 웹 검색·LLM 응답 시간 편차 영향
- **RAGAS reference 한계:** 모범 답안이 아니라 `expected` 항목 목록을 reference 로 써서 context_recall·precision 은 참고값
